# scripts/

Operational scripts (db reset, release helpers, smoke checks, asset generators) land here as milestones need them.

- `gen-icons.mjs` (`pnpm gen:icons`) — reproducible brand icon/splash raster generation.
- `gen-sounds.mjs` (`pnpm gen:sounds`) — reproducible UI sound-effect + call-ring synthesis (one brand sound family, LUFS-normalized) for both desktop and mobile; `--preview --out=tmp/sfx` builds the old-vs-candidates listening page. See `docs/product/sound-credits.md`.
- `deploy.sh` (on the VPS) / `deploy-remote.sh` — server release. `deploy.sh` also owns the **Caddy config sync**: a bind-mounted `Caddyfile` whose contents change does not make compose recreate the container, and the single-file mount pins an inode that `git reset --hard` leaves behind — so the proxy silently keeps its old config and `caddy reload` re-reads the same stale file (production incident, 2026-07-27). It compares the in-container file with the repo's, validates and force-recreates caddy on a mismatch, then **proves** the result (admin-API vhost list + a real request through the public edge) instead of reporting success. See `docs/architecture/deploy.md` → "Shipping a Caddy change".
- `lib/remote-ssh.sh` — the **only** sanctioned way to reach the VPS. Verifies the pinned `DEPLOY_HOSTKEY` on the OpenSSH path too (build a `known_hosts` from `ssh-keyscan` output, keep only fingerprint matches, `StrictHostKeyChecking=yes`) instead of the `accept-new` that used to hand the root password to whatever answered first, and keeps the password out of `argv` (`sshpass -e`, PuTTY `-pwfile`). Sourcing it is enforced by `check-deploy-scripts.mjs`.
- `publish-desktop.sh` / `publish-web.sh` / `publish-landing.sh` / `publish-mobile-apk.sh` — per-channel publish + verify.
- `build-desktop-mac.sh` — dispatches `.github/workflows/desktop-mac.yml`, waits for it, and unpacks the artifacts into `apps/desktop/release/<version>/` ready for `publish-desktop.sh --mac`. Needs `GITHUB_TOKEN` in `.env.deploy`.
- `check-caddyfile.mjs` (`pnpm lint:caddy`, also part of `pnpm lint`) — structural + invariant check on the production `Caddyfile`: braces balance, **no duplicate site address** (Caddy refuses to load one, taking the stack down), every site address built from `{$DOMAIN}`, the host set matches DNS exactly, no `turn.*` vhost, no dead `karagozali.com` reference in a live directive, the web CSP `connect-src` still reaches the backend without an over-broad source, and the `/download/windows` redirect still matches the installer name `electron-builder.yml` produces. Needs no Caddy binary. Run `caddy validate --config Caddyfile --adapter caddyfile` (with `DOMAIN`/`ACME_EMAIL` set) for real syntax validation.
- `check-deploy-scripts.mjs` (`pnpm lint:deploy`, also part of `pnpm lint`) — the fast half of the deploy hardening: no script waives the SSH host key or puts the password in argv, every remote script sources `lib/remote-ssh.sh`, `deploy.sh` keeps its stop → up → prove → remove order with the rollback trap armed, `APP_ENV: production` is pinned in `docker-compose.prod.yml`, and the dev compose publishes nothing beyond loopback.
- `test-remote-ssh.sh` + `test-deploy-migration.sh` (`pnpm test:deploy`) — the behavioural half, kept out of `pnpm lint` because it is slow on Windows. The first generates two real ed25519 keys and asserts the impostor is refused; the second drives `deploy.sh` against a fake Docker and asserts the ordering, the rollback (containers **and** host directories restored), the pre-created-target refusal, and that a feed 404 fails the deploy.
- `smoke-*.mjs` — milestone smoke checks.
