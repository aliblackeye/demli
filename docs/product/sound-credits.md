# UI Sound Credits

The app's UI sound effects are **original, synthesized in-repo** — no third-party
samples, no license obligations. They are generated by
[`scripts/gen-sounds.mjs`](../../scripts/gen-sounds.mjs) (pure Node PCM synthesis;
optional ffmpeg for the Ogg encode) and written to both clients:

- Desktop: `apps/desktop/src/renderer/src/sounds/assets/*.ogg`
- Mobile: `apps/mobile/assets/sounds/*.ogg` (+ the two ring `*.wav` cadences)

Regenerate with `pnpm gen:sounds` (or `node scripts/gen-sounds.mjs`). The script
is the source of truth; the committed assets are its output.

## Families (founder picks one)

The generator ships **four complete families**. The motifs (which notes, which
direction) are shared, so the meaning of every cue is identical whichever is
active; only the timbre changes.

| id        | Name          | Character                                                         |
| --------- | ------------- | ----------------------------------------------------------------- |
| `marimba` | Sıcak Marimba | Rosewood bar, soft mallet, warm low-mid body. Organic, friendly.   |
| `glass`   | Yumuşak Cam   | Struck glass/bell, bright "tink", airy shimmer. Clean, premium.    |
| `felt`    | Keçe Tahta    | Felt-beater tongue drum + breath layer. Dark, plump, unobtrusive.  |
| `legacy`  | Eski set      | The original sine design — kept only to reproduce the pre-2026-07-29 set. |

```bash
node scripts/gen-sounds.mjs --preview        # all four → build/sound-previews/ + index.html
node scripts/gen-sounds.mjs                  # write ACTIVE_FAMILY to BOTH clients
```

**Shipped: `felt` (Keçe Tahta), since 2026-07-29.** The founder listened to all
four and picked it. It is the darkest candidate (centroid 665-1041 Hz, only
3-8% of energy above 3 kHz) — deliberate for a cue heard hundreds of times a day:
it sits under the conversation instead of cutting through it.

`ACTIVE_FAMILY` at the top of the script is what a bare `pnpm gen:sounds` writes,
and it **must** name the family committed under the asset directories. The script
refuses a `--family=` run that would leave the two disagreeing, because otherwise
the next bare run silently reverts every sound — a regression with no diff to
review and no test to fail. Switching means changing that constant and running
the generator **in the same commit**; it rewrites `apps/mobile/assets/sounds/`
too, so both clients keep one sound identity.

## Design language

Physical-ish **modal synthesis**, the way a UI sound designer builds a cue:

| Layer    | What it is                                                                   |
| -------- | ---------------------------------------------------------------------------- |
| `strike` | A few ms of band-limited noise — the mallet/finger hitting the object.        |
| `modes`  | An **inharmonic** partial stack with **per-partial decay** (highs die first). |
| `body`   | A short low sine under the hit, so the cue has weight.                        |
| `room`   | Schroeder reverb (4 damped combs → 2 allpasses), RT60 ≈ 0.3 s, mixed faint.   |
| `level`  | Normalized by **loudness** (max 50 ms sliding RMS), not by peak.              |

Partial ratios are the instrument's identity: marimba `1 : 3.93 : 9.42`, glass
`1 : 2.76 : 5.40 : 8.93`, wood `1 : 2.57 : 4.95`. Peak ceiling is −4.5 dBFS on
every cue (pure gain, never a limiter, so nothing is ever distorted or clipped);
48 kHz mono throughout.

### Why the previous design was replaced

Measured on the shipped assets, not guessed:

- **1–4 spectral peaks per cue.** The harmonic recipe `[1, 0.16, 0.06]` puts
  partial 2 at −16 dB and partial 3 at −24 dB. It was a sine.
- **Spectral centroid 234–1570 Hz, 85 % rolloff ≤ 1570 Hz, 0.0–1.3 % of energy
  above 3 kHz.** The band that reads as "crisp" was empty.
- **`<300 Hz` energy 0.1 %** on every cue but `mute` (92 %, a dull lone A3 hum).
  No body.
- **No transient.** A smoothstep attack on a sine is an oscillator turning on,
  not an object being struck.
- **One global exponential decay** for the whole spectrum — the synthesizer tell.
- **Crest factor 9.8–11.0 dB on all nine cues**: every sound was the same *kind*
  of sound (a sustained tone), with no percussive contrast anywhere in the set.
- **Peak-normalizing everything to one ceiling** flattened the hierarchy:
  `message` landed only 2 dB under `screen-start`.
- The "reverb" was 4 taps at 17/29/41/57 ms — flutter-range slapback, i.e. a
  metallic comb filter, not a room.

The new families answer each of those: 2–9 partials, centroid 665–2600 Hz with
3–30 % of the energy above 3 kHz (the dark family low, the glass family high),
real `<300 Hz` body, a noise transient, frequency-dependent decay, crest 12–21 dB,
and a loudness-based hierarchy.

## Motif family

Rising = positive, its counterpart falls; one key, so the whole app speaks in one
musical voice.

| App sound          | Cue meaning                       | Motif                             |
| ------------------ | --------------------------------- | --------------------------------- |
| `voice-join.ogg`   | You joined a voice channel        | C5 → G5 rising fifth              |
| `voice-leave.ogg`  | You left a voice channel          | G5 → C5 falling fifth             |
| `peer-join.ogg`    | Someone joined your voice channel | G4 → C5 rising fourth, softer     |
| `peer-leave.ogg`   | Someone left your voice channel   | C5 → G4 falling fourth, softer    |
| `mute.ogg`         | Microphone muted                  | F4, damped + dull strike          |
| `unmute.ogg`       | Microphone unmuted                | C5, open + bright (a fifth above) |
| `screen-start.ogg` | Screen share started              | C5-E5-A5 rising                   |
| `screen-stop.ogg`  | Screen share stopped              | A5-E5-C5 falling                  |
| `message.ogg`      | New message notification          | D5 → F5 rising minor third        |

(The `legacy` family keeps the older intervals it was built with; the table above
describes the three modal families.)

## Loudness hierarchy

Targets are **loudness** (max 50 ms sliding RMS), which is what the ear compares —
the old peak targets could not express a hierarchy at all.

| Cue                                     | Target     |
| --------------------------------------- | ---------- |
| `ring-incoming`                         | −13 dBFS   |
| `voice-join/leave`, `screen-start/stop` | −15 dBFS   |
| `ring-outgoing`                         | −16 dBFS   |
| `unmute`                                | −16.5 dBFS |
| `mute`                                  | −17.5 dBFS |
| `peer-join/leave`                       | −18 dBFS   |
| `message`                               | −20 dBFS   |

`message` is deliberately the quietest: it fires most often and must never feel
like an alarm. Runtime user volume scales from there (`sounds/sound-settings.ts`).

## Call ring cadences (mobile assets)

The looping call rings are generated as full-period WAV loops so `player.loop`
reproduces the desktop cadence seamlessly (desktop synthesizes its ring live in
`sounds/ringtone.ts`, so it needs no asset):

| Asset               | Cue      | Period                 |
| ------------------- | -------- | ---------------------- |
| `ring-incoming.wav` | Incoming | C5 + G5 double, 2.60 s |
| `ring-outgoing.wav` | Outgoing | A4 ringback, 3.40 s    |

The ring notes and periods match `sounds/ringtone.ts` (desktop) so the two
platforms share the same call-ring identity.
